07 / TARGET ARCHITECTURE

Public stays available. Private stops being public.

PUBLIC REQUEST CHAINUser → Cloudflare edge → application

DNS → managed edge TLS → DDoS → bot signals → WAF → rate limiting → API controls → Worker or origin.

INSPECT + ENFORCE ON ONE PATH
PRIVATE REQUEST CHAINUser → Access policy → Tunnel → private resource

Authenticate identity and context first; allow only authorized requests over outbound-only connectivity.

REMOVE UNNECESSARY EXPOSURE

Takeaway: AppSec protects what must remain public. Access and Tunnel reduce exposure for admin, preview, internal, and partner paths.

Public traffic ↗ Open Access applications ↗ Open Tunnels/connectors ↗

17 / APPENDIX · TLS + ORIGIN TRUTH

Two designs.
Two TLS stories.

Universal SSL automates the edge certificate lifecycle. It does not by itself prove a conventional origin is authenticated or inaccessible directly.

THIS WORKER CUSTOM DOMAINCloudflare is the application origin

The visitor negotiates edge TLS with Cloudflare. The route invokes Worker code; no conventional second web-origin certificate is presented or validated.

EDGE TLS ONLY FOR THIS ROUTE
CONVENTIONAL PROXIED ORIGINSecure both connections

Visitor-to-Cloudflare TLS is followed by a separate Cloudflare-to-origin connection, normally Full (strict) with a valid origin certificate and origin protection.
